## 1. Executive Summary & Architectural Scope

Card **GW-002** implements the external-facing **HTTPS / TLS 1.3 server endpoint** for the **SecureCloud API Gateway** (`securecloud-gateway`). It builds directly upon the foundational HTTP server and routing engine established in **GW-001** and consumes the cryptographic material generated by the development PKI in **SC-009**.

### Key Invariants & Architectural Boundaries
1. **Strict TLS 1.3 / No Insecure Downgrade (ADR-004, Gateway Design 3.24, 3.25)**:
   - External clients connect to the Gateway exclusively over HTTPS + TLS 1.3.
   - Handshake attempts utilizing SSLv3, TLS 1.0, TLS 1.1, or deprecated/insecure cipher suites must be rejected immediately during the TLS handshake.
   - Any secondary cleartext HTTP listener must either be disabled or operate strictly as an unauthenticated HTTP 308 Permanent Redirect to the canonical HTTPS port.
2. **Fail-Closed Certificate & Key Validation**:
   - The Gateway must validate the server certificate and private key at startup before binding sockets.
   - If the certificate file is missing, unreadable, expired, corrupted, or mathematically mismatched with the private key, the Gateway must abort startup immediately with an actionable error. It must never fall back to an unencrypted socket or dummy self-signed certificate.
3. **Transport-Level Resource & Denial-of-Service Limits (Gateway Design 3.23, 3.24)**:
   - Enforce bounded request headers (`max_header_size` <= 16 KB; excess returns `431 Request Header Fields Too Large`).
   - Enforce bounded non-streaming request bodies (`max_body_size` <= 10 MB; excess returns `413 Payload Too Large`).
   - Configure socket read/write/idle timeouts to eliminate Slowloris and connection-exhaustion attack vectors.
   - Bound maximum concurrent connections (`max_connections`).
4. **Strict No-Database Invariant (ADR-005, Gateway Design 3.1)**:
   - The Gateway owns **zero business data persistence**. It must never configure, connect to, or bundle drivers for PostgreSQL, ScyllaDB, MinIO, or ClickHouse.
5. **Strict Observational Host PostgreSQL 14 Guard**:
   - Workstation host PostgreSQL 14 runs on `localhost:5432`. No Gateway test or process may attempt to connect to, stop, or reconfigure port `5432`.
6. **M1 Non-Regression Invariant**:
   - All Milestone 1 capabilities, CMake build presets, protobuf generation targets, mTLS credential loaders, and `verify-local.py` orchestration must continue passing cleanly across macOS (AppleClang), Windows (MSVC x64), and Windows (MinGW-w64).

### GW-002-T02 — OpenSSL TLS Context & Certificate Pair Validator (`TlsHandler`)

1. **Ticket ID**: `GW-002-T02`
2. **Title**: OpenSSL TLS Context & Certificate Pair Validator (`TlsHandler`)
3. **Objective**: Implement `TlsHandler` encapsulating OpenSSL `SSL_CTX` initialization, mathematical keypair matching, strict TLS 1.3 protocol clamping, and ALPN negotiation.
4. **Architectural Purpose**: Guarantees cryptographically sound TLS context initialization, fail-closed startup on corrupt/mismatched keys, and eliminates protocol downgrade vulnerabilities (Gateway Design 3.23 `TlsHandler`, 3.24 Invariants 1 & 12).
5. **Scope**:
   - Create `src/gateway/tls/tls_handler.hpp` and `src/gateway/tls/tls_handler.cpp`:
     - Method `bool validate_certificate_pair(const std::string& cert_path, const std::string& key_path, std::string& out_error)`:
       - Loads x509 cert via `PEM_read_bio_X509()`.
       - Loads private key via `PEM_read_bio_PrivateKey()`.
       - Calls `X509_check_private_key()` to mathematically verify the key belongs to the certificate.
       - Validates expiration (`X509_get0_notAfter()`).
     - Method `SSL_CTX* create_server_context(const GatewayTlsConfig& config)`:
       - Initializes OpenSSL server context via `TLS_server_method()`.
       - Enforces minimum protocol version:
         ```c
         SSL_CTX_set_min_proto_version(ctx, TLS1_3_VERSION);
         SSL_CTX_set_max_proto_version(ctx, TLS1_3_VERSION); // or 0 for future-proof
         ```
       - Configures approved TLS 1.3 ciphersuites via `SSL_CTX_set_ciphersuites()`.
       - Disables session tickets, renegotiation, and TLS compression (`SSL_OP_NO_COMPRESSION`).
       - Configures ALPN callback supporting `"h2"` and `"http/1.1"`.
       - Loads server certificate chain and private key into `SSL_CTX`.
     - Ensures proper OpenSSL cleanup (`X509_free`, `EVP_PKEY_free`, `SSL_CTX_free`) using RAII smart pointers.
   - Unit tests in `tests/unit/gateway/tls_handler_test.cpp`:
     - Validates valid certificate/key pair from `deploy/dev-pki/services/gateway/`.
     - Validates rejection of mismatched key (e.g., pairing `gateway.crt` with `auth.key`).
     - Validates rejection of corrupted/truncated certificate files.
     - Validates context enforces `TLS1_3_VERSION`.
6. **Explicit Out-of-Scope**: Listening on TCP sockets; handling HTTP request bodies.
7. **Dependencies**: Upstream GW-002-T01, SC-009. Downstream GW-002-T03.
8. **Exact Repository Starting Point**: `src/gateway/CMakeLists.txt`.
9. **Files/Directories to Create**:
   - `src/gateway/tls/tls_handler.hpp`
   - `src/gateway/tls/tls_handler.cpp`
   - `tests/unit/gateway/tls_handler_test.cpp`
10. **Files/Directories That May Be Modified**:
    - `src/gateway/CMakeLists.txt`
    - `tests/unit/CMakeLists.txt`
11. **Files/Directories That MUST NOT Be Modified**: `src/common/*`, `src/auth/*`.
12. **Detailed Implementation Requirements**:
    - OpenSSL RAII custom deleters:
      ```cpp
      struct SslCtxDeleter { void operator()(SSL_CTX* ctx) const { if (ctx) SSL_CTX_free(ctx); } };
      struct X509Deleter { void operator()(X509* x) const { if (x) X509_free(x); } };
      struct EvpPkeyDeleter { void operator()(EVP_PKEY* p) const { if (p) EVP_PKEY_free(p); } };
      ```

### GW-002-T04 — Request & Resource Limiter Middleware (Transport Bounds)

1. **Ticket ID**: `GW-002-T04`
2. **Title**: Request & Resource Limiter Middleware (Transport Bounds)
3. **Objective**: Implement transport-level and pre-routing resource constraints enforcing `max_header_size` (HTTP 431) and `max_body_size` (HTTP 413), with bounded execution times.
4. **Architectural Purpose**: Protects the Gateway against resource exhaustion, memory exhaustion, unbounded buffers, and Slowloris denial-of-service attacks (Gateway Design 3.23 `ResourceLimiter`, 3.24 Invariant 13).
5. **Scope**:
   - Create `src/gateway/middleware/resource_limiter_middleware.hpp` and `src/gateway/middleware/resource_limiter_middleware.cpp`:
     - Checks total header size of incoming request:
       - If sum of header keys and values exceeds `limits.max_header_bytes`, abort further handling and return:
         - Status: `431 Request Header Fields Too Large`
         - Header: `Content-Type: application/problem+json`
         - Body: JSON error envelope `{"type": "urn:securecloud:error:header_too_large", "title": "Request Header Fields Too Large", "status": 431}`
     - Checks payload body size:
       - Inspect `Content-Length` header if present. If > `limits.max_body_bytes`, immediately reject with:
         - Status: `413 Payload Too Large`
         - Header: `Content-Type: application/problem+json`
         - Body: JSON error envelope `{"type": "urn:securecloud:error:payload_too_large", "title": "Payload Too Large", "status": 413}`
       - Ingest body with length cap; if actual streamed bytes exceed limit, terminate connection immediately.
     - Connection limiter counter:
       - Atomic counter of active connections. If current count exceeds `limits.max_concurrent_connections`, reject with:
         - Status: `503 Service Unavailable`
         - Header: `Retry-After: 5`
   - Register middleware in `Router` pipeline.
   - Unit tests in `tests/unit/gateway/resource_limiter_middleware_test.cpp`.
6. **Explicit Out-of-Scope**: Large chunked streaming file uploads (owned by GW-007 / FILES-001).
7. **Dependencies**: Upstream GW-002-T01, GW-001-T04. Downstream GW-002-T06.
8. **Exact Repository Starting Point**: `src/gateway/http/router.hpp`.
9. **Files/Directories to Create**:
