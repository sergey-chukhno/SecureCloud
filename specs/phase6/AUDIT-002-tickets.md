## 1. Executive Summary & Architectural Scope

Card **AUDIT-002** specifies the implementation of the authoritative, transport-independent **Canonical Audit Event Domain Model** (`AuditEvent`) and a deterministic, fail-closed **Validation Engine** (`AuditEventValidator`) for the SecureCloud Audit Service (`securecloud-audit`).

As defined in **ADR-001**, **ADR-006**, **ADR-008**, and `docs/data-model/05-audit-data-model.md`, the Audit Service is the centralized, immutable security and operational auditing authority for SecureCloud. Before audit events can be queued into ingestion worker pools or flushed in batches to **ClickHouse**, they must pass strict syntactic, semantic, bounded-resource, and security validation.

### Key Invariants & Architectural Boundaries for AUDIT-002

1. **Single Canonical Event Model (ADR-006, Audit Data Model 5.5)**:
   A single, strongly typed C++20 domain model (`AuditEvent`) serves as the internal representation across all ingestion transports (gRPC, internal event bus) and analytical query paths. Ingestion transports deserialize incoming payloads directly into this model without creating competing or divergent schemas.
2. **Deterministic, Pure Domain Validation (SC-012, Audit Design 7.1–7.4)**:
   The validation engine (`AuditEventValidator`) is a pure domain component completely decoupled from network transport (gRPC), persistence engines (ClickHouse), or external operating system state. Given an `AuditEvent` and policy limits, validation must be deterministic, stateless, and thread-safe.
3. **Strict UUIDv7 Event Identity & Idempotency (Audit Data Model 5.6, RFC 9562)**:
   Every audit event must be identified by an RFC 9562 UUIDv7 generated by the producing service. UUIDv7 guarantees global uniqueness, chronological ordering, and k-sortable indexing in ClickHouse. The validator must strictly enforce UUID version `7` (variant `10xx`) and reject malformed, nil, or non-v7 UUIDs.
4. **Temporal Dual-Timestamp Integrity (Audit Data Model 5.7)**:
   Every event records two distinct UTC timestamps:
   - `occurred_at`: Producer-assigned business/security event timestamp. Validated against clock-drift bounds (rejected if $>5$ minutes in the future or older than the configured retention floor).
   - `received_at`: Service-assigned ingestion timestamp, stamped authoritatively by the Audit Service ingestion layer upon intake. Ingestion paths must never trust or allow external overwrite of `received_at`.
5. **Producer Identity Authenticity & Authorization (Audit Data Model 5.2, ADR-008)**:
   Producer identity is never trusted merely because a payload names a service string. The validator verifies that the declared `producer_service` strictly matches the authenticated mTLS client peer identity (SAN/CN) from the transport `CallerContext`.
   - Allowed producers: `gateway`, `auth`, `messaging`, `files`, and internal `audit`.
6. **Zero-Plaintext & Content Confidentiality Guard (ADR-008, Audit Design 7.6)**:
   Audit events must never become a side-channel for secrets or plaintext payloads. The validator and sensitive data defense guard must reject events containing:
   - Message plaintext or decrypted message bodies.
   - Plaintext file contents or file-encryption keys.
   - User credentials, passwords, password hashes, MFA secrets/codes, session/refresh tokens, or private keys.
   - Error messages, validation traces, and diagnostic logs must **never** reflect raw input payloads when rejecting malformed or prohibited fields.
7. **Strict Bounded Payload & Metadata Limits (ADR-010, Audit Config IngestionConfig)**:
   To prevent denial-of-service (DoS) via memory exhaustion, hard boundaries are enforced before allocating heap memory or queuing:
   - Event wire size: bounded by `max_event_size_bytes` (default 64 KB, absolute maximum 1 MB).
   - Metadata key count: maximum 50 entries.
   - Metadata key length: maximum 64 characters (restricted to alphanumeric, dots, underscores, dashes).
   - Metadata value length: maximum 1024 characters.
   - Identifier lengths (`actor_id`, `target_id`, `correlation_id`): bounded to 128 / 64 characters.

       - Helpers: `to_string(TargetType)` (`"USER"`, `"DEVICE"`, `"CONVERSATION"`, `"FILE"`, `"SERVICE"`, `"UNKNOWN"`), `target_type_from_string(std::string_view)`.
   - Create `src/audit/domain/event_id.hpp`:
     - Strongly typed RFC 9562 UUIDv7 value object:
       ```cpp
       class EventId {
       public:
           using bytes_type = std::array<uint8_t, 16>;
           constexpr EventId() noexcept = default;
           constexpr explicit EventId(const bytes_type& bytes) noexcept : bytes_(bytes) {}

           [[nodiscard]] static EventId generate_v7();
           [[nodiscard]] static std::optional<EventId> from_string(std::string_view sv) noexcept;
           [[nodiscard]] std::string to_string() const;

           [[nodiscard]] constexpr const bytes_type& bytes() const noexcept { return bytes_; }
           [[nodiscard]] constexpr bool is_nil() const noexcept { return bytes_ == bytes_type{}; }
           [[nodiscard]] uint8_t version() const noexcept { return static_cast<uint8_t>((bytes_[6] >> 4) & 0x0F); }
           [[nodiscard]] uint8_t variant() const noexcept { return static_cast<uint8_t>((bytes_[8] >> 6) & 0x03); }
           [[nodiscard]] uint64_t timestamp_ms() const noexcept;

           constexpr auto operator<=>(const EventId& other) const noexcept = default;
           constexpr bool operator==(const EventId& other) const noexcept = default;
       private:
           bytes_type bytes_{};
       };
       ```
   - Create `src/audit/domain/audit_event.hpp`:

       struct AuditEvent {

       };

### AUDIT-002-T02 — Deterministic Domain Validation Engine & Boundary Enforcer

1. **Ticket ID**: `AUDIT-002-T02`
2. **Title**: Deterministic Domain Validation Engine & Bounded Resource Limits Enforcer
3. **Objective**: Implement `AuditEventValidator` providing pure, deterministic validation of all required fields, UUIDv7 integrity, timestamp drift rules, enumeration sanity, and bounded metadata limits.
4. **Architectural Purpose**: Ensures that no invalid, malformed, out-of-range, or oversized audit event enters the ingestion queue or reaches persistent storage.
5. **Scope**:
   - Create `src/audit/domain/validation_result.hpp`:
     - Structured error reporting:
       ```cpp
       enum class AuditValidationErrorCode {
           Success = 0,
           MissingRequiredField,
           InvalidEventId,
           EventIdNotUuidV7,
           ClockSkewFuture,
           ClockSkewTooOld,
           ReceivedAtBeforeOccurredAt,
           InvalidEventTypeFormat,
           InvalidSeverity,
           UnauthorizedProducer,
           PayloadOversized,
           MetadataCountExceeded,
           MetadataKeyInvalid,
           MetadataKeyOversized,
           MetadataValueOversized,
           ActorIdOversized,
           TargetIdOversized,
           CorrelationIdInvalid,
           CausationIdInvalid,
           SensitiveDataDetected
       };

       struct AuditValidationError {
           AuditValidationErrorCode code;
           std::string field;
           std::string message;
       };

       class AuditValidationResult {
       public:
           [[nodiscard]] static AuditValidationResult ok() noexcept;
           [[nodiscard]] static AuditValidationResult failure(AuditValidationError error);
           [[nodiscard]] bool is_valid() const noexcept { return errors_.empty(); }
           [[nodiscard]] const std::vector<AuditValidationError>& errors() const noexcept { return errors_; }
       private:
           std::vector<AuditValidationError> errors_;
       };
       ```
   - Create `src/audit/domain/audit_event_validator.hpp|cpp`:
     - Define `AuditEventValidationLimits`:
       ```cpp
       struct AuditEventValidationLimits {
           size_t max_event_size_bytes{65536};        // 64 KB default, up to 1 MB
           size_t max_metadata_entries{50};
           size_t max_metadata_key_length{64};
           size_t max_metadata_value_length{1024};
           size_t max_event_type_length{64};
           size_t max_producer_instance_length{64};
           size_t max_actor_id_length{128};
           size_t max_target_id_length{128};
           size_t max_correlation_id_length{64};
           size_t max_causation_id_length{64};
           std::chrono::seconds max_future_skew{300}; // 5 minutes max clock drift
           std::chrono::hours max_past_age{24 * 365}; // 1 year historical window
       };
       ```
     - Implement validation logic in `AuditEventValidator`:
       - `validate(const AuditEvent& event, const AuditEventValidationLimits& limits, std::chrono::system_clock::time_point now)`
       - **Rule 1: Event ID**: Must be non-nil and valid UUIDv7 (`version() == 7` and `variant() == 2` [RFC 4122]).
       - **Rule 2: Event Type**: Must not be empty, length $\le 64$, must conform to lowercase alphanumeric with dots (e.g. `^[a-z0-9_]+(\\.[a-z0-9_]+)+$`), matching namespace patterns (`auth.*`, `msg.*`, `files.*`, `gateway.*`, `audit.*`).
       - **Rule 3: Occurred At**: Must satisfy `occurred_at <= now + limits.max_future_skew` and `occurred_at >= now - limits.max_past_age`.
       - **Rule 4: Received At**: If present, must satisfy `received_at >= occurred_at - limits.max_future_skew`.
       - **Rule 5: Actor & Target**: `actor_type` must not be `Unknown` if `actor_id` is specified; `actor_id` length $\le 128$; `target_id` length $\le 128$.
       - **Rule 6: Correlation ID**: If present, length $\le 64$ and must consist of printable ASCII characters without whitespace.
       - **Rule 7: Metadata Bounded Limits**:
         - Number of entries $\le 50$.
         - Keys: length $\le 64$, strictly printable ASCII (matching `^[a-zA-Z0-9_.-]+$`).
         - Values: length $\le 1024$.
       - **Rule 8: Approximate In-Memory Size**: Total serialized memory footprint bounded by `max_event_size_bytes`.
6. **Explicit Out-of-Scope**: Reading certificates or parsing gRPC metadata (handled in T04 and T05).
7. **Dependencies**: `AUDIT-002-T01`.
8. **Files to Create/Modify**:
   - `src/audit/domain/validation_result.hpp`
   - `src/audit/domain/validation_result.cpp`
   - `src/audit/domain/audit_event_validator.hpp`
   - `src/audit/domain/audit_event_validator.cpp`
   - `src/audit/CMakeLists.txt`

### AUDIT-002-T03 — Content Confidentiality Guard & Sensitive Data Defense Engine

1. **Ticket ID**: `AUDIT-002-T03`
2. **Title**: Content Confidentiality Guard & Sensitive Data Defense Engine
3. **Objective**: Implement `SensitiveDataGuard` to prevent sensitive credentials, cryptographic secrets, or plaintext user data from being accepted into audit records or leaked into error diagnostics.
4. **Architectural Purpose**: Enforces the Zero-Plaintext and Zero-Secret invariants of **ADR-008** and Audit Design 7.6 at the domain boundary, preventing audit logs from becoming an attack vector or side-channel.
5. **Scope**:
   - Create `src/audit/domain/sensitive_data_guard.hpp|cpp`:
     - Implement blocklist key inspection:
       - Forbidden substrings in metadata keys (case-insensitive):
         `"password"`, `"passwd"`, `"secret"`, `"token"`, `"credential"`, `"private_key"`, `"privkey"`, `"mfa"`, `"totp"`, `"plaintext"`, `"seed"`, `"salt"`, `"api_key"`.
     - Implement value pattern heuristics:
       - Rejects values containing PEM certificate/key headers: `-----BEGIN PRIVATE KEY-----`, `-----BEGIN RSA PRIVATE KEY-----`, `-----BEGIN EC PRIVATE KEY-----`.
       - Rejects potential JWT structures: three Base64URL-encoded segments separated by periods (`eyJ...`).
     - Safe error generation & redaction:
       - `std::string sanitize_diagnostic(std::string_view raw)`: Strips and replaces any sensitive data with `[REDACTED]`.
       - When a sensitive key or value is detected, the error message must state:
         `"Sensitive key forbidden in metadata: '<key>' contains prohibited credential term"` or `"Value contains prohibited secret or key material"`.
       - The raw rejected value itself must **never** be logged or included in the `AuditValidationError` string.
     - Integrate `SensitiveDataGuard::inspect(const AuditEvent& event)` into `AuditEventValidator::validate()`.
6. **Explicit Out-of-Scope**: End-to-end payload decryption (Audit never possesses decryption keys).
7. **Dependencies**: `AUDIT-002-T01`, `AUDIT-002-T02`.
8. **Files to Create/Modify**:
   - `src/audit/domain/sensitive_data_guard.hpp`
   - `src/audit/domain/sensitive_data_guard.cpp`
   - `src/audit/domain/audit_event_validator.cpp`
   - `src/audit/CMakeLists.txt`

1. **Ticket ID**: `AUDIT-002-T04`

3. **Objective**: Implement `ProducerIdentityValidator` to verify that the declared `producer_service` in the event payload authoritatively matches the authenticated mTLS client peer identity.
4. **Architectural Purpose**: Enforces the invariant that "Producer identity is not trusted merely because a payload names a service." A compromised or misbehaving service cannot forge audit events claiming to be another service.
5. **Scope**:
   - Create `src/audit/domain/producer_identity_validator.hpp|cpp`:
     - Define `PeerIdentity`:
       ```cpp
       struct PeerIdentity {
           std::string common_name;
           std::vector<std::string> san_dns_names;
           std::vector<std::string> san_uri_names;
           bool is_authenticated{false};
       };
       ```
     - Define allowed service identity mappings:
       - `ProducerService::Gateway` $\leftrightarrow$ SAN/CN `gateway.securecloud.internal`, `gateway`
       - `ProducerService::Auth` $\leftrightarrow$ SAN/CN `auth.securecloud.internal`, `auth`
       - `ProducerService::Messaging` $\leftrightarrow$ SAN/CN `messaging.securecloud.internal`, `messaging`
       - `ProducerService::Files` $\leftrightarrow$ SAN/CN `files.securecloud.internal`, `files`
